# 10. Help and Documentation

**Definition**: It's best if the system doesn't need additional explanation. However, it may be
necessary to provide documentation to help users understand how to complete their tasks.

**Accessibility Lens**: Help content and documentation must itself be accessible. Tooltips and
contextual help that only appear on mouse hover are inaccessible to keyboard and assistive
technology users — they must be reachable and perceivable through all input methods.
Context-sensitive help must not vanish before the user can read it. Complex custom controls benefit
from usage instructions that describe how to interact with them (e.g., how to navigate between
options). Error states should connect to relevant help content. Watch for elements that appear
interactive or helpful but lead to no meaningful outcome — a help link that opens an empty page, a
tooltip that restates the label without adding information, or an affordance that promises
functionality the user cannot access. These inviting dead ends waste the user's effort and erode
trust.
