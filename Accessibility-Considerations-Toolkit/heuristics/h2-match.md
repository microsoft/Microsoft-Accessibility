# 2. Match Between System and Real World

**Definition**: The design should speak the users' language. Use words, phrases, and concepts
familiar to the user, rather than internal jargon. Follow real-world conventions, making information
appear in a natural and logical order.

**Accessibility Lens**: Users of assistive technology build expectations from how an element is
represented to them. If something looks and behaves like a button visually but is conveyed
semantically as plain text, the user's understanding of what it is and how to interact with it is
broken. Elements must be represented in a way that matches their actual behaviour — a control
described as a button that behaves like a link violates the user's expectations. Icon-only controls
without text labels force the user to guess meaning. Beyond names and roles, look for elements whose
meaning or required interaction is unclear — a control that is perceived by the user but whose
purpose cannot be understood from the information available to them is an uncomprehended element,
even if it is technically present in the interface.
