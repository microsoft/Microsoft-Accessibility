# Title–Evidence Consistency

Before finalizing each finding, verify that:

1. **The title accurately reflects what the evidence describes.** Do not use alarmist language
   (e.g., "focus trap") if the evidence shows exit mechanisms exist. The title should describe the
   actual observed problem, not a hypothetical worst case.

2. **The severity matches the actual impact described in the evidence**, not the worst-case implied
   by the title. A misleading title that escalates perceived severity undermines trust in the
   evaluation.

3. **The recommendation addresses the actual problem**, not a hypothetical. If the evidence
   describes a minor friction point, the recommendation should address that friction — not prescribe
   a solution for a catastrophic failure that wasn't observed.

## Why This Matters

Evaluations that overstate problems lose credibility. A developer or designer who reads "keyboard
trap" and discovers the user can press Escape to exit will discount future findings. Precision in
language preserves the evaluator's authority and the reader's trust.

## Checklist

For each finding before submission:

- [ ] Title describes the observed problem accurately
- [ ] Evidence supports the title's claim
- [ ] Severity rating matches evidence, not title tone
- [ ] Recommendation addresses the evidenced problem
- [ ] User impact narrative is grounded in the evidence, not extrapolated beyond it
